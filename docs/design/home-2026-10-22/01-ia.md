Date: 2026-10-22. Role: product and information architecture agent (read-only for code).
Baseline: `main` at 9a5b297, app label `Peach Prep 2.2.0-rc (PP-003)` (confirmed from `js/data/manifest.js` at runtime).
Worktree: `/home/claude/pp-home`, branch `design/home-start-experience`.

This document maps the home journeys as they currently work, lists what the app actually saves, and proposes the homepage hierarchy. File references point to the baseline source. Copy shown in quotes is illustrative; the copy agent (03-copy.md) owns final wording. The visual agent (02-visual.md) owns composition.

## 0. Summary of decisions

1. **Keep the three existing root screens and their routes.** The "homepage" is mode-aware:
   - `#screen-choose` is the first-visit home. It also serves families with saved work but no mode.
   - `#screen-path` is the returning home for Learning Path families.
   - `#screen-home` (the catalog) is the returning home for families who browse lessons.

   This keeps every hash, direct link and Back/Forward behaviour, and every existing test assertion about which screen the site root opens. A single new root screen would break `path.py` "completed: root remembers path mode", "browse preference survives reload" and guard 12.6/12.8 (§5). It would also force selector rewrites that change behaviour.
2. **Exactly one primary button per home state.** Today the browse home has two primaries: `#up-next-btn` and "Follow the Learning Path" (`index.html:85`).
3. **"Continue" means reopening a lesson at a saved step tab, nothing more.** The Learning Path bookmark (`pp.path.v1.bookmark = {key, step}`) is the only saved resume point. It reopens the lesson's step tab: the Learn It panel, the Practice Together card, and so on. It does not reopen a question inside practice, Try or the check. Unfinished check answers are not restored (verified in a browser, §1.4). Never write "continue where you left off".
4. **Lesson browsing is one tap away from every home state**, without changing the saved mode unless the parent asks to switch.
5. **One shared "How a lesson works" explainer and one shared support-links row**, rendered on all three home screens below the primary action. The explainer includes the hands-on exceptions and the grown-up roles.
6. **No new storage key is required.** Every state below is detected from existing keys by reading only. One optional additive field is discussed in §3.6 and is not recommended for this release.

## 2. Proposed homepage information architecture

### 2.1 State detection (existing storage only, reads only)

Rendering must never write (guard 11.1 requires that opening and rendering write nothing). Add read-only helpers. Put them in a new `js/home.js`, or export them from `js/path.js` and `js/skills.js`. Every `localStorage` access goes in `try/catch`.

| State | Rule | Root screen |
|---|---|---|
| **S0 New** | `PP_PATH.mode()===null` and no lesson record in `pp.progress.v1` (ignore `_ui`), no `pp.task.*` with a draft, no `pp.skwrite.*` with text | `#screen-choose`, first-visit variant |
| **S1 Saved work, no mode** | `mode===null` and any of the S0 conditions false | `#screen-choose`, "welcome back" variant |
| **S2 Path, in progress** | `mode==="path"` and `current()` not null | `#screen-path` |
| **S3 Path, all finished** | `mode==="path"` and `current()===null` | `#screen-path` (existing honest text) |
| **S4 Browse** | `mode==="browse"` | `#screen-home` |
| **S5 Storage blocked** | `storageOK===false` (`js/path.js:9-26`) or progress read threw | Any of the above, plus the existing `.path-storage` notice |

Derived values (all pure reads):

- `started = Object.keys(PP.lessons).filter(k => PP_SKILLS.status(k)==="started")`
- `passed = …status(k)==="mastered"`
- `reviewDue = …filter(PP_SKILLS.reviewDue)`
- `drafts` = tasks whose `pp.task.<id>` has non-empty `draft`
- `nextStepFor(k)` = first step id whose done flag is false, using the same map as `renderSteps` (`js/skills.js:626`: `teach←taught`, `learn←learned`, `practice←practiced`, `try←tried`, `test←mastered`), restricted to `stepsFor(L)`
- Path: `PP_PATH.current()`, `bookmark` and `firstUnfinished = entries().find(k => !done(k))`. These need **new read-only exports** from `js/path.js:231`; today only `mode`, `entries` and `phases` are exported.
- Step label for a bookmark: map ids to `PP_SKILLS.stepNames(k)` (`js/skills.js:1336`). The ids are `["teach","learn","practice","try","test"]` with `"try"` removed when names has four entries, because Try is the only optional step.

### 2.2 First visit (S0): `#screen-choose`

Order, top to bottom:

1. **Brand line** `p.brand` "Peach Prep · Grade 3 ELA".
2. **h1 `#choose-title`** (keep the id; fresh visitors get focus here, `path.py:31`) plus **one "what this is" line** (`.page-sub`). Example: "Free lessons for Georgia's grade 3 reading, writing and grammar standards. You and your child work through each lesson together."
3. **Two choice cards** (`.learning-choices`), Path first:
   - **Follow the Learning Path**: badge "Recommended starting point". One line: "A suggested order through all of grade 3 ELA, starting with stories and sentences. It is not a test or a placement."
     - A **three-item preview** of how it works: "Open the next lesson" → "Work through its steps together, over one or more short sessions" → "Mark it finished, or open any lesson anytime".
     - **Primary button `#choose-path`**, keeping the id and the ≥44px height. Label "Follow the Learning Path" in S0. It calls `PP_PATH.open()` → `#path` with `#path-intro` → **Start** (`#path-start`, primary) and "View the Full Path" (`#path-preview`).
     - The two-step "choose → intro → Start" flow is kept deliberately: `path.py:34-39` asserts it. The intro is the full preview; the card carries the short one.
   - **Choose a Lesson**: one line: "Pick a skill your child needs or match what the class is learning. Search 99 lessons and two essay tasks by word or standard code, or filter to skills on the test."
     - **Secondary button `#choose-browse`** (soft). It calls `PP_PATH.browse()` → `#browse`. Rename the visible label from "Choose Individual Lessons" to "Choose a Lesson" if copy agrees.
     - Optional, low cost: five category shortcuts (Foundations, Reading, Writing, Vocabulary, Grammar). Each calls `PP_PATH.browse()` and then clicks the matching `.cat-card[data-cat]`, which reuses the existing scroll and focus handler at `js/skills.js:421-433`. Note that this writes `_ui.lastCat`, which is acceptable because the click is a user action.
4. **Saving note** (existing `.note`) and **`.path-storage`** status. Keep both on this screen.
5. *Below the fold:* the shared **routine explainer** (§2.6), then the shared **support row** (§2.7).

There is one primary action (`#choose-path`). The Choose card's button is visually secondary but must look like a real choice, not a footnote.

### 2.3 Saved work but no mode (S1): `#screen-choose`, welcome-back variant

This is the same screen and the same ids, with two additions above the cards:

- **Status line** (`role="status"`). Example: "This browser has saved work: 12 lessons started, 5 skill checks passed, 1 essay draft. Either choice keeps it." Counts come from §2.1, with number words below ten.
- **"Lessons you started"**: up to three `started` lessons in catalog order, plus "See all in the lesson list". Each is a soft button that opens `PP_SKILLS.open(k, nextStepFor(k))`, labelled "Open at Try It Yourself (first unchecked step)". This is honest because the step bar shows the same ✓ marks.

The cards are as in S0. The Path card's button label becomes "Follow the Learning Path" as before. Clicking Choose a Lesson keeps everything.

*Why:* today a pre-path family with passes sees a blank first-visit screen (§1.3). Existing scores are deliberately **not** converted into path completion (`LEARNING-PATH-IMPLEMENTATION-REVIEW.md:33`; `path.py:114`). Keep that.

7. **Full path** (`#path-phase-*`, `.path-lesson-group`, `[data-path-key]`, `#path-finished-N`, `#path-habit-N`): structure unchanged.
8. Below: the shared **routine explainer** and **support row**. Keep the bottom "Choose Individual Lessons" button (`js/path.js:216`), relabelled to match.

### 2.6 Shared "How a lesson works" explainer (below the fold)

Build it once (e.g. `PP_HOME.routine(host)`) and insert it into `#screen-choose` (open), `#screen-path` (open, after the full path, or collapsed above it, as the visual agent decides) and `#screen-home` (collapsed `<details>`).

Content, which must match the code (§1.7):

- **Five steps** Learn It → Watch Me → Practice Together → Try It Yourself → Test Your Knowledge, with one short line each, and who does it:
  - Learn It: together.
  - Watch Me: together, revealing a worked example one step at a time.
  - Practice Together: together, with Help me hints, not scored.
  - Try It Yourself: the child alone; help after one wrong try.
  - Test Your Knowledge: the child alone, no hints; passing is 80% of the points (rounded up); some checks alternate between two forms.
- "A lesson can take more than one short session."
- **Exceptions:**
  - Four hands-on lessons (reading aloud and cursive writing) use Learn It → Watch Me → Practice → Check, where a grown-up listens or looks at handwriting and checks it off.
  - Two essay tasks use Read → Plan → Write → Check → For parents, where a grown-up scores with the rubric.
- **Where a grown-up joins in:** listen, watch, check handwriting, read and score writing (one icon or line each).
- **What marks mean**, matching the existing labels:
  - ✓ = passed a skill check.
  - "✓ grown-up" = checked by a grown-up.
  - ◐ = started.
  - Path "Activities finished" = the family's own bookmark.
  - None of these means the child can apply the skill independently. **Do not use the words master, mastered or mastery in text visible on `#screen-home`** (guard 11.15). On `#screen-path`, the existing "not proof of mastery" and "does not establish mastery" strings must remain (`path.py:35,123`). Phrase the shared component without that word, and leave those two strings where they are.
- **Saving, briefly:** "Saved in this browser on this device. Clearing browser data erases it. An unfinished check is not saved." Link to the parent guide's "How to use" tab (`#parents/plan`, which already has "Check progress", `js/data/site.js:110`).

### 3.3 Words, accessibility and layout

- **Wording:** guard 11.15 fails if visible home text contains "master", "mastered" or "mastery" (Georgia grammar-chart "Master" labels excepted). The path screen must keep its two existing phrases.

Gradients, translucent panels or images behind text on these two screens will fail it. - **Direct links:** `#skill/...`, `#write/...`, `#play/...`, `#parents/...` and `#browse` must keep working in every mode. `#path` with `introduced:false` must still show the intro.

### 3.5 Bookmark and storage semantics

- **Bookmark drift:** in path mode any `#skill` or `#write` visit moves the bookmark (`js/path.js:59-68`). The proposed "Suggested next on the path" line (§2.4) makes this visible instead of changing it. Do not change `track()` without new compatibility tests.

  - The S1 detection loops over `localStorage` keys and must be guarded. Under blocked storage (`path.py:105`) the home must still render S0 with the notice and no page error.
  - `Object.keys(localStorage)` throws when the getter throws.

### 3.6 Optional future field (not recommended now)

Recording the last lesson opened in browse mode would need a new additive field, e.g. `pp.path.v1.lastOpened = {key, step}` written in `track()` for every mode. It would add a new write on lesson open (guard 11.1 only checks `pp.progress.v1`, so it would pass). It would also need explicit compatibility tests per the brief's migration rule. The IA above works without it, and recommends deferring it.
